# 销售数据周报(演示用合成数据)

> **重要说明:本报告全部基于 `sales.csv` 中的合成 (synthetic) 数据,不是真实客户或真实业务数据。所有数字仅用于演示数据处理与可视化流程,不代表任何真实经营结果,也不构成因果结论。**

## 一、数据概况

- 文件:`sales.csv`,共 **12 行数据**(不含表头),列:week, channel, orders, revenue_cny。
- 时间范围:**2026-W35 ~ 2026-W38,连续 4 周**;渠道 3 个:App、Web、MiniProgram。
- 数据质量检查:
  - 缺失值:**各列均为 0**。
  - 重复 (week, channel) 组合:**无**(12 行 = 4 周 × 3 渠道,结构完整)。
  - 类型:orders、revenue_cny 全部为可解析的整数,**无需清洗**。
- 因此本次计算直接使用原始数据,未做去重或填补。

## 二、汇总结果(全部渠道,4 周合计)

| 渠道 | 订单数 | 收入 (CNY) | 客单价 (CNY) |
|---|---:|---:|---:|
| Web | 175 | 54,330 | 310.46 |
| App | 172 | 56,060 | 325.93 |
| MiniProgram | 131 | 36,280 | 276.95 |
| **TOTAL** | **478** | **146,670** | **306.84** |

(客单价 = 收入 ÷ 订单数,保留 2 位小数;合计行用小计收入与小计订单重新计算。)

## 三、最新一周 vs 首周收入增长(按渠道)

首周 = 2026-W35,最新周 = 2026-W38。

| 渠道 | 首周 W35 收入 | 最新周 W38 收入 | 增长率 |
|---|---:|---:|---:|
| Web | 12,000 | 15,360 | **+28.00%** |
| App | 9,000 | 19,720 | **+119.11%** |
| MiniProgram | 6,500 | 11,600 | **+78.46%** |
| **合计** | **27,500** | **46,680** | **+69.75%** |

周度合计收入:W35 = 27,500 → W36 = 34,210 → W37 = 38,280 → W38 = 46,680(逐周上升)。

## 四、3 条观察

1. **App 与 Web 收入体量接近,是主力渠道**:4 周收入分别为 56,060 与 54,330,合计占总额 (146,670) 的约 38.2% 和 37.0%;MiniProgram 为 36,280,约占 24.7%。
2. **App 的客单价最高,但增长结构不同**:App 客单价 325.93,高于 Web 的 310.46 和 MiniProgram 的 276.95;同时 App 从 W35 到 W38 收入增长 +119.11%,是三个渠道中增幅最大的(订单数 30 → 58)。
3. **MiniProgram 客单价最低、收入规模最小**:客单价 276.95(比 App 低约 49 元),4 周收入仅 36,280,是收入占比最低的渠道。

## 五、2 条下一步建议

1. **核对总计口径与数据完整性**:当前数据无缺失、无重复,建议在后续实际取数时保持同样的 (week, channel) 唯一性校验,并确认客单价使用"收入 ÷ 订单数"的一致口径,避免跨口径比较。
2. **补充分维度数据再下结论**:合成数据显示 App 增幅最大,但仅凭 4 周合计无法判断原因。建议补充流量来源、活动日历、商品结构等字段后再做分析,以便区分是渠道变化、活动影响还是数据本身波动。
